# TOMRIS — Next.js-проект

Полноценный проект на Next.js App Router + React + TypeScript с текущим дизайном TOMRIS. Главная, портфолио, услуги, контакты, AZ / RU / EN, три авторские SMM-иллюстрации, фильтрация и просмотр работ, мобильное меню и подготовка брифа.

## Быстрый запуск

Установите Node.js 20.9 или новее. Проект проверен на Node.js 24.

```bash
cd tomris-nextjs
npm ci
npm run dev
```

Откройте http://localhost:3000. Изменения в исходниках отображаются автоматически.

## Production-сборка

```bash
npm run typecheck
npm run build
npm run start
```

## Docker

Для production-запуска установите Docker с Compose v2:

```bash
docker compose up -d --build --wait
docker compose logs -f web
```

Сайт доступен на http://localhost:3000. Порт можно изменить: `PORT=8080 docker compose up -d --build --wait`.
Остановка: `docker compose down`.

Dockerfile использует Node.js 24 и многоэтапную standalone-сборку Next.js. Контейнер работает от пользователя `node`, содержит сервер, статические файлы и `public`; healthcheck проверяет главную страницу. Локальные `.env*` и служебные каталоги исключены из контекста сборки. Если появятся серверные секреты, передавайте их контейнеру через `environment` или `env_file` в Compose; переменные `NEXT_PUBLIC_*` необходимо задавать при сборке.

## CI в GitHub Actions и деплой на Vercel

Workflow `.github/workflows/ci-cd.yml` запускается для pull request, push в `main`/`master` и вручную через Actions. Он устанавливает зависимости через `npm ci`, генерирует типы маршрутов, проверяет TypeScript и выполняет production-сборку Next.js на Node.js 24. Секреты для CI не нужны. Для защиты основной ветки добавьте обязательную проверку `TypeScript and production build` в правила ветки.

Деплой выполняет встроенная [интеграция Vercel с GitHub](https://vercel.com/docs/git/vercel-for-github):

1. В Vercel выберите **Add New → Project** и импортируйте этот GitHub-репозиторий.
2. Выберите Framework Preset **Next.js**, Root Directory — корень репозитория, Node.js — **24.x**. Оставьте стандартные Build Command и Output Directory.
3. В настройках Git проекта укажите Production Branch `master` (текущая основная ветка), либо `main`, если переименуете её.
4. Нажмите **Deploy**. После подключения Vercel автоматически создаёт production-деплои основной ветки и preview-деплои других веток и pull request.

SSH, серверные ключи и публикация Docker-образа для Vercel не нужны. Переменные окружения приложения задаются в настройках проекта Vercel. Dockerfile и Compose остаются для локального production-запуска или самостоятельного хостинга.

GitHub Actions и Vercel запускаются независимо: ошибка CI сама по себе не блокирует деплой Vercel. Обязательная проверка CI в правилах основной ветки блокирует слияние pull request с ошибками; для блокировки публикации самим Vercel настройте [Deployment Checks](https://vercel.com/docs/deployment-checks), если они доступны для вашего проекта.

## Языки

Маршруты: `/`, `/portfolio`, `/services`, `/contacts`.

Язык указывается параметром: `/?lang=az`, `/?lang=ru`, `/?lang=en`. Выбор сохраняется в cookie `tmr-language`. Сервер сразу отрисовывает тексты на выбранном языке, затем переключение работает через React. Форма сохраняет введённые значения при смене языка.

## Анимации

Композиция главной следует референсам `samples/desktop.png` и `samples/mobile.png`: асимметричный терракотовый фон, арочная иллюстрация, крупная светлая типографика, рукописная подпись и наклонная лента услуг. Фигурные фоны и иллюстрации продолжают этот стиль в портфолио, услугах и контактах.

Прокрутка управляет наклоном картин и фонов, вращением звёзд, движением ленты и раскрытием изображений через фигурные маски. Заголовок появляется построчно. Стандартная прокрутка браузера сохраняется; дополнительные библиотеки не требуются. Обновления выполняются через `requestAnimationFrame` только при прокрутке, изменении размеров и содержимого, а положение секций отслеживается рядом с экраном.

Параметры CSS-анимаций задаются переменными `--motion-fast`, `--motion-reveal`, `--motion-ease` в `src/app/motion.css`. Для появления элемента добавьте `data-reveal="up"`, `"left"`, `"right"` или `"art"`; `data-delay="1"`–`"4"` задаёт задержку. Для построчного появления добавьте `data-reveal="line"` на обёртку `.title-line` с текстом во вложенном `span`. `data-parallax="18"` ограничивает смещение иллюстрации 18 пикселями в каждую сторону. `data-scroll-scene` на секции включает переменные `--scene-progress`, `--scene-entry`, `--scene-exit` для движения её слоёв. Появление срабатывает один раз; после фильтрации новые карточки анимируются снова.

На телефоне параллакс выключен, а наклоны и смещения уменьшены. Системная настройка `prefers-reduced-motion` отключает анимации и плавную прокрутку, включая изменение настройки во время просмотра; без JavaScript серверный контент остаётся видимым. Меню, окна и услуги сохраняют стандартное управление с клавиатуры.

## Добавить работу в портфолио

1. Положите изображение в `public/assets/`.
2. Добавьте имя файла в `projectAssets` и индекс категории в `projectCategories` файла `src/data/projects.ts`.
3. Добавьте `[название, категория, описание]` в `projects` каждой локали файла `src/data/translations.ts` — порядок должен совпадать с `projectAssets`.
4. Выбор работ на главной задаётся через `<PortfolioGrid selected={[1, 2]} />`.

Индекс категории соответствует порядку массива `categories`. Имена файлов должны быть локальными, например `my-project.jpg`.

## Что уже работает и что нужно подключить

Бриф формируется локально, копируется и скачивается как TXT. Почтовая отправка, CRM, база данных и административная панель пока не подключены. Для отправки можно добавить Route Handler, например `src/app/api/contact/route.ts`, и вызывать его из `contacts-view.tsx`. Ключи почтового сервиса храните на сервере в `.env.local`, а не в переменных `NEXT_PUBLIC_*`.

Портфолио сейчас содержит художественные концепции TOMRIS, а не клиентские кейсы. Их можно заменить реальными проектами.

Иллюстрации сохранены локально. Futura включена в виде поднабора символов, извлечённого из предоставленного брендбука; для отсутствующих букв используются резервные шрифты. При наличии полной лицензированной версии Futura замените соответствующие файлы и `@font-face`. Другие комплектные шрифты и их лицензии описаны в `ASSETS.md`.

## Развитие проекта

Создайте новый маршрут, например `src/app/about/page.tsx`, и добавьте ссылку в `studio-shell.tsx`. Серверную логику можно добавлять через Route Handlers Next.js или подключить отдельный HTTP API. В проекте нет зависимости от ChatGPT/Sites: для локального запуска достаточно Node.js и npm.

Документация: https://nextjs.org/docs
